# Bank – Umsetzungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bank-Buchungen laufen sicher unter Sperre in einer discord-freien Fachschicht, der Zinssatz ist eindeutig, und die Einstellungen liegen im `/panel`.

**Architecture:** `demolizzen/services/bank.py` enthält jede Buchung als Funktion mit Transaktion und Zeilensperre. Die Cogs `Bank` und `BankAdmin` rufen nur diese Funktionen auf und zeigen deren Ergebnis oder Fehlertext. Eine Einstellungsseite meldet sich wie beim Ticketsystem beim Panel an.

**Tech Stack:** Python ≥ 3.11, py-cord 2.8.x, Django 5.2 (async ORM), Tests: `python runtests.py demolizzen --debug-mode`.

**Spec:** `docs/superpowers/specs/2026-11-15-bank-design.md`

## Global Constraints

- `demolizzen/services/**` importiert nie `discord`.
- Beträge: `int`, `1 ≤ amount ≤ 1_000_000_000_000`; `bool` ist kein Betrag.
- Kein Kontostand wird negativ; `debit(..., clamp=True)` zieht höchstens ab, was da ist.
- Zinssatz als Anteil gespeichert; neu einstellbar `0 ≤ rate ≤ 0.10`; Auszahlung wöchentlich, abgerundet.
- Bestehende Kontostände und Zinssätze unter 1 bleiben unverändert.
- Bot-Texte englisch. Jeder Commit lässt Tests grün und den Bot startbar; `pre-commit run --all-files` läuft durch.
- `makemigrations` mit `DJANGO_SETTINGS_MODULE=testenv.settings` und `--skip-checks`.

## Review Focus

1. Zwei Buchungen desselben Kontos kurz nacheinander: die zweite rechnet mit dem Stand aus der Datenbank, nicht mit einem zuvor geladenen Objekt. → Aufgabe 1
1. Empfänger ohne Profil oder Konto (hat den Bot nie benutzt): Überweisung und Gutschrift legen es an, kein Absturz. → Aufgabe 1
1. Betrag 0, negativ, riesig oder `True`: abgelehnt mit klarem Text, nichts gebucht. → Aufgabe 1
1. Zinsen bei Server ohne Konten, mit Satz 0 und mit abgeschaltetem Modul: kein Fehler, keine Auszahlung, Fälligkeit bleibt korrekt. → Aufgaben 2 und 4
1. Gegenläufige Überweisungen A→B und B→A: Sperren immer in derselben Reihenfolge. → Aufgabe 1

### Task 1: Konten und Buchungen

**Files:** Create `demolizzen/services/bank.py`, `demolizzen/tests/services/test_bank.py`; Modify `demolizzen/services/errors.py`

**Interfaces – Produces:**

- `errors.BankError(ServiceError)` mit `.message`; Unterklassen `InvalidAmount`, `InsufficientFunds`, `BankActionDisabled`, `InvalidTransfer`, `InvalidBankSetting`
- `bank.MAX_AMOUNT = 1_000_000_000_000`
- `bank.Balance` – `@dataclass(frozen=True)`: `wallet: int`, `bank: int`
- `async bank.ensure_account(guild_id, user_id, user_name) -> UserBankAccount` – legt Profil (über `guilds.ensure_members`) und Konto bei Bedarf an; `GuildNotRegistered` ohne Guild-Profil
- `async bank.get_balance(guild_id, user_id, user_name) -> Balance`
- `async bank.deposit(guild_id, user_id, user_name, amount) -> Balance` – `BankActionDisabled`, wenn `allow_deposits` aus
- `async bank.withdraw(guild_id, user_id, user_name, amount) -> Balance` – `BankActionDisabled`, wenn `allow_withdrawals` aus
- `async bank.transfer(guild_id, sender_id, sender_name, receiver_id, receiver_name, amount) -> Balance` – Stand des Absenders; `InvalidTransfer` bei gleichem Mitglied; sperrt beide Konten aufsteigend nach Primärschlüssel
- `async bank.credit(guild_id, user_id, user_name, amount, account="wallet") -> Balance`
- `async bank.debit(guild_id, user_id, user_name, amount, account="wallet", clamp=False) -> int` – tatsächlich abgezogener Betrag; ohne `clamp` → `InsufficientFunds`
- `async bank.reset(guild_id, user_id, user_name) -> None`
- `account` ist `"wallet"` oder `"bank"`, sonst `InvalidAmount`-fremder `ValueError`

Fehlertexte: `Amount must be at least 1.`, `Amount is too large.`, `You don't have that much money!`, `Deposits are disabled on this server.`, `Withdrawals are disabled on this server.`, `You can't send to yourself...`

### Task 2: Einstellungen, Zinsen, Migration der Zinssätze

**Files:** Modify `demolizzen/services/bank.py`, `demolizzen/models/guild.py` (Hilfetext `interest_rate`); Create `demolizzen/migrations/0011_bank_interest_rate_fraction.py`, `demolizzen/tests/services/test_bank_interest.py`

**Interfaces – Produces:**

- `bank.MAX_INTEREST_RATE = 0.10`, `bank.INTEREST_PERIOD = timedelta(days=7)`

- `async bank.get_settings(guild_id) -> GuildBankSettings`

- `async bank.update_settings(guild_id, **fields) -> GuildBankSettings` – nur `interest_rate` (`0 ≤ x ≤ 0.10`, `int` oder `float`), `allow_deposits`, `allow_withdrawals` (`bool`); sonst `InvalidBankSetting`

- `async bank.due_guild_ids(guild_ids, now=None) -> list[int]` – Guilds, deren `last_interest_update` fehlt oder mindestens `INTEREST_PERIOD` zurückliegt

- `async bank.pay_interest(guild_id, now=None) -> int` – in einer Transaktion: Fälligkeit unter Sperre erneut prüfen (nicht fällig → `0`), `bank = bank + FLOOR(bank * rate)` für alle Konten der Guild als ein `UPDATE`, `last_interest_update = now`; Rückgabe = Zahl der Konten mit positivem Bank-Stand

- `migrations/0011`: `RunPython` – `interest_rate ≥ 1` → `min(rate / 100, 0.10)`; Rückwärtsrichtung ohne Wirkung; Funktion `convert_rate(rate: float) -> float` im Migrationsmodul

**Files:** Rewrite `demolizzen/cogs/banksystem/banksystem.py`, `banksystem_admin.py`; Create `demolizzen/tests/cogs/test_bank_cog.py`
